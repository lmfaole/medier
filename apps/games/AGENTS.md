# AGENTS.md — games

> **Serving (changed 2026-11):** this app is no longer a Cloudflare Worker with a published snapshot. It is Astro on Node, one of the eight media apps in the single server on the owner's machine (`scripts/media-server.ts`, the `media` container, `docs/MEDIA-SERVER.md`): dynamic server rendering, the database opened read-only, behind the owner's Nextcloud login (so "public" below means "behind that login"). Built with `npm run media:build`, live after `systemctl --user restart media`. There is no `<app>-publish` timer, no `npm run deploy` and no `wrangler.jsonc` any more; where this file says snapshot, publish or Worker for this app, read it as the server's live read of `.data/`. The sync timers stay.

`sky.lmfaole.party/apps/medier/spill`: the video games the owner has played, from the log and the Steam library, and what the register IGDB says about them, a snapshot of `.data/games.db`. Public and not indexed (the three
layers, as music). Rules shared with every app are in the root `AGENTS.md`; the counting, the lists and the pages
themselves are `@designsystem/shelf`, shared with the other two shelf apps (games, books, boardgames).

**The log is the record**: `.data/games-log.csv`, written by hand and added to by a service
(`date,title,year,status,rating,amount,note,ext_id,source,format`, `#` starts a comment; an empty `date` is a line whose day is
not known; `rating` is 0.5 to 5 in half steps). `status` is `playing`, `done`, `dropped` (an empty status is `playing`); `amount` is hours. `ext_id` is the register's number (it settles a wrong
match), `source` the service's own number for the line (it is how a pull knows it has added it, so never edit it away). `format` is what the owner has (`cd`, `vinyl`, `digital`, `blu-ray`, `steam`, a platform; free text, lowercase, several with commas) and is shown as «Eier» on the work's page and in the library.

Steam's library goes to the collection as `owned` (format `steam`); a game with hours is also a `playing` line of the log.

Commands from `apps/games`: `cargo run -p games-sync -- import-log | add <title> <year> <date> <rating> | settle <title> <ext_id> | remove <title> (takes a title out of the collection, keeping a copy as `games-collection.csv.before-remove`; the log is not touched) | steam | romm | psn | pokemon-go | xbox | xbox-api | steam-achievements | retroachievements | igdb [--everything]`, `npm run snapshot`, `npm run deploy`.
Timers: `schedule.json` runs `import-log` after `steam` and `igdb` daily, `igdb --everything` on Sundays (`node scripts/sync-timers.ts games install`, with `STEAM_API_KEY`, `STEAM_ID`, `IGDB_CLIENT_ID`, `IGDB_CLIENT_SECRET`, `RA_USER` and `RA_API_KEY` in `~/.config/games-sync.env`, mode 600), and `node scripts/publish-timers.ts games install` publishes after the Sunday refresh.
The statuses are in two places that have to agree: `SHELF` in `sync-rust/src/main.rs` and the config in `web/src/server/api.ts`.
