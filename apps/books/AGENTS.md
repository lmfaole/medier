# AGENTS.md — books

> **Serving (changed 2026-11):** this app is no longer a Cloudflare Worker with a published snapshot. It is Astro on Node, one of the eight media apps in the single server on the owner's machine (`scripts/media-server.ts`, the `media` container, `docs/MEDIA-SERVER.md`): dynamic server rendering, the database opened read-only, behind the owner's Nextcloud login (so "public" below means "behind that login"). Built with `npm run media:build`, live after `systemctl --user restart media`. There is no `<app>-publish` timer, no `npm run deploy` and no `wrangler.jsonc` any more; where this file says snapshot, publish or Worker for this app, read it as the server's live read of `.data/`. The sync timers stay.

`sky.lmfaole.party/apps/medier/boker`: the books the owner has read, from the log and the Hardcover shelves, and what the register Open Library says about them, a snapshot of `.data/books.db`. Public and not indexed (the three
layers, as music). Rules shared with every app are in the root `AGENTS.md`; the counting, the lists and the pages
themselves are `@designsystem/shelf`, shared with the other two shelf apps (games, books, boardgames).

**The log is the record**: `.data/books-log.csv`, written by hand and added to by a service
(`date,title,year,status,rating,amount,note,ext_id,source,format`, `#` starts a comment; an empty `date` is a line whose day is
not known; `rating` is 0.5 to 5 in half steps). `status` is `done`, `reading`, `dropped` (an empty status is `done`); `amount` is pages. `ext_id` is the register's number (it settles a wrong
match), `source` the service's own number for the line (it is how a pull knows it has added it, so never edit it away). `format` is what the owner has (`cd`, `vinyl`, `digital`, `blu-ray`, `steam`, a platform; free text, lowercase, several with commas) and is shown as «Eier» on the work's page and in the library.

**The library is the collection and the log together**: `.data/books-collection.csv` (the log's columns; `status` is `owned` or `want`, empty means `owned`) is made the collection table by `books-sync import-collection`, so a work needs no line in the log to be in the library or to have a page; the log counts only what was played or read. Hardcover's want-to-read shelf and Goodreads' to-read are lines of the collection (`want`); the books of the other shelves are the log's.

The `note` of a line stays in the database: it is never read for a page, so it is never published.

| Where | What |
| --- | --- |
| `sync-rust/src/hardcover.rs` | Hardcover, in both directions, and **Hardcover wins**. `books-sync hardcover` makes `hardcover_book` and `hardcover_read` exactly what the API returns (landed under `.data/raw/hardcover/<date>/`) and lays them over `book_entry` (`overlay`, run after every import): a book Hardcover has takes its status, rating, day and pages from Hardcover whatever the log says (the log's line, title and note stay), and a book the log lacks is added from it. The writes send a change to Hardcover first and then pull again: `rate <title> <rating>`, `status <title> <want\|reading\|done\|dropped>`, `read <title> <started> <finished> <pages>` (`-` for none; the latest read, or its first), `shelve <title> <year> <status>` (found by search; no sure match says the candidates) and `push-hardcover` (the log's own lines, those with no `hardcover:` source, are shelved with their rating and dates, a finished book with no day is left out because Hardcover would give it today's, and Hardcover's number is written into each sent line's `source`; the file as it was is kept once as `books-log.csv.before-hardcover`). A title is found among the shelved books by name (spelled the same, else the only one that contains it). Every write has `--dry-run`, which needs no token and sends nothing. `HARDCOVER_TOKEN`, from hardcover.app/account/api. Not run against the live API yet: the mutations are those other Hardcover clients use (`insert_user_book`, `update_user_book`, `insert_user_book_read`, `update_user_book_read`), so try `--dry-run` first, then one book |
| `crates/shared-data/src/purchases.rs` (`books-sync purchases`) | The audiobooks of the Audible receipts `mail-ingest` landed, from `.data/mail-purchases.json` (`npm run mail:purchases`): each is `owned` in the collection once, by its `source` (`mail:audible:<title>`), format `audiobook`. Only the title is read; the facts come from Open Library as for any book |
| `sync-rust/src/apple.rs` | `books-sync apple`: the books and audiobooks bought in Apple Books, from the landed Apple data export (`npm run land -- apple-media <zip>`, `Store Transaction Purchase and Free Apps History.csv`): each `owned` once (`applebooks:<item number>`, format `apple books` or `apple lydbok`) on the day it was bought. Price, invoice, device and account are not read |
| `sync-rust/src/goodreads.rs` | `books-sync goodreads <file or folder>`: the books of a Goodreads library export (My Books, Import and export, Export Library; Goodreads has no open API) that the log lacks are appended (by `source`, `goodreads:<Book Id>`). Keep the export first: `npm run land -- goodreads <file>`, which prints this command. Shelves read, currently-reading and to-read, and shelves named dnf, did-not-finish or abandoned, become `done`, `reading`, `want` and `dropped`; the series in the title is dropped; the private notes and the review are not read. The other export Goodreads gives, the personal data request (a zip of zips of JSON, landed the same way), is read from the same command: it has no Book Id, so its shelvings, ratings and reading days are matched by title (`goodreads:title:<title>`) and a book whose title the log already has is left alone |
| `sync-rust/src/openlibrary.rs` | `books-sync openlibrary`: looks each title the log names up in Open Library (no key), lands the answers under `.data/raw/openlibrary/<date>/` and stores the work (`book_item`: author, first year, description, cover address; `book_genre`: the first subjects). A title no search matches is kept in `book_match` with its candidates; settle it by writing the work's number (`OL…W`) in the log's `ext_id` |
| `crates/shared-data/src/shelf.rs` | The log, the register tables and the search, shared by the three tools: reading and checking a line (a wrong line is refused with its line number), `import`, `append`, `append_new`, `resolve`, `fetch_items`, and the `main` every tool has (`Tool`) |
| `packages/contracts/src/shelf-tables.ts` | The tables the pages read and `shelfLinesSql`: a line and the work matched to it (the log's number first, else the match for its title and year) |
| `web/src/server/api.ts`, `snapshot.ts`, `responses.ts` | The API files (`overview`, `library`, `history`, `entity?slug=`); the counting is `packages/shelf/src/shelf.ts`, the schemas `@designsystem/shelf/responses` |
| `web/src/pages/*.astro`, `views/shelf.tsx` | Astro pages: `/bok/[slug]` hydrates its chart `client:visible`, `/bibliotek` is `client:idle`, `/` and `/historikk` (a year at a time, `?year=YYYY`; an old `?month=` link lands on its year) are plain HTML. `views/shelf.tsx` closes `words.ts` (functions) over the shelf views, since props cannot carry functions. `/minner` is not edge cached (it shows today) |
| `packages/shelf/src/pages/`, `views.tsx` | The shared pages and `shelfViews(words, kind)`, with Open Library's credit (`Credit`) |
| `scripts/fetch-shelf-covers.ts` | After the snapshot: lands the covers it names under `.data/raw/shelf-covers/books/` and copies them to `web/public/covers/` (only from a register's own host: `packages/shelf/src/covers.ts`) |

Commands from `apps/books`: `cargo run -p books-sync -- import-log | add <title> <year> <date> <rating> | hardcover | rate | status | read | shelve | push-hardcover [--dry-run] | goodreads <export> | openlibrary [--everything]`, `npm run snapshot`, `npm run deploy`.
Timers: `schedule.json` runs `import-log` after `hardcover` and `openlibrary` daily, `openlibrary --everything` on Sundays (`node scripts/sync-timers.ts books install`, with `HARDCOVER_TOKEN` in `~/.config/books-sync.env`, mode 600), and `node scripts/publish-timers.ts books install` publishes after the Sunday refresh.
The statuses are in two places that have to agree: `SHELF` in `sync-rust/src/main.rs` and the config in `web/src/server/api.ts`.
