# AGENTS.md — podkast

> **Serving (changed 2026-11):** this app is no longer a Cloudflare Worker with a published snapshot. It is Astro on Node, one of the eight media apps in the single server on the owner's machine (`scripts/media-server.ts`, the `media` container, `docs/MEDIA-SERVER.md`): dynamic server rendering, the database opened read-only, behind the owner's Nextcloud login (so "public" below means "behind that login"). Built with `npm run media:build`, live after `systemctl --user restart media`. There is no `<app>-publish` timer, no `npm run deploy` and no `wrangler.jsonc` any more; where this file says snapshot, publish or Worker for this app, read it as the server's live read of `.data/`. The sync timers stay.

`sky.lmfaole.party/apps/medier/podkast`: what the owner listens to in podcasts, a snapshot of `.data/podcasts.db`. Public and not
indexed (the three layers, as music). Rules shared with every app are in the root `AGENTS.md`.

| Where | What |
| --- | --- |
| `packages/contracts/src/podcast-tables.ts` (`podcastPlaysWithListeningSql`) | What a play is, from three sources: a play of a minute or more in Spotify's export, a scrobble, and what the player recorded through gpodder (`podcast_history`, attached; the latest action of an episode, from a minute in, a bulk mark of ten or more in one second left out), a listening two sources have counted once. «Sist spilt» on the front page and `/history` are the same list |
| `packages/contracts/src/podcast-tables.ts` | The tables of `db/podcasts.sql` podkast reads and `PODCAST_PLAYS_SQL`, what a play is: Spotify's plays of a minute or more, plus the scrobbles (ListenBrainz names the show as the artist, Last.fm as the track) that Spotify does not have within six hours |
| `sync-rust/src/` | `podkast-sync import`: the gpodder log (AntennaPod, through Nextcloud's gpoddersync) from `export/gpodder-episode-actions.jsonl` in the Nextcloud repository (`~/Dokumenter/nextcloud`, `NEXTCLOUD_DIR`) into `podcast_history.db` (`episode_actions`, every play, pause, seek and finish; idempotent), every three hours at :35 from `schedule.json` (`node scripts/sync-timers.ts podkast install`). That repository writes the file after its database dump every three hours at :30 (`gpodder-export.ts`); this crate knows nothing else of Nextcloud. The scrobbles come with music's sync, the shows' feeds and countries with its weekly mode, and Spotify's export by hand |
| `sync-rust/src/feeds.rs` | The title of a recorded episode, from the feed the player listens through: AntennaPod may use a mirror of a show's feed (the NRK shows come through two public mirrors) that Apple's directory does not know, so `feeds.rs` fetches it, lands it under `.data/raw/podcast-feeds/<date>/gpodder-*.xml`, puts the show under the name `podcasts.db` knows by its title, and finds each episode by the media URL the player had |
| `web/src/server/podcast-stats.ts` | The counting, as pure functions of the plays: top shows and episodes, totals, per year, per hour (Oslo time) |
| `web/src/server/api.ts`, `snapshot.ts`, `responses.ts` | `overview.json`, `history.json?month=` and the entity files; `responses.ts` is the valibot schema of each file the pages read (`RESPONSES`) |
| `web/src/pages/`, `layouts/PodkastPage.astro`, `views/` | Astro pages: `/`, `/historikk` and the own page of `/show/[slug]` and `/episode/[slug]`. Each reads its snapshot file with `readPage` and a `RESPONSES` schema; the island wrappers in `views/` (a function cannot cross the island boundary) draw it with the shared pages of `packages/ui`. Directives: `client:visible` for `/statistikk` and the two own pages (charts), `client:idle` for `/bibliotek`, plain HTML for the rest. A show or an episode in a list is a link to `?kort=<kind>.<slug>`: `PodkastPage` reads it and sends the `Detail` card island (`client:idle`) only then |
| `web/src/lib/slugs.ts`, `links.tsx`, `server/page-data.ts`, `server/podcast-stats.ts` (`entitiesOf`, `showPageOf`, `episodePageOf`, `slugOf`) | `/show/[slug]` and `/episode/[slug]`: an index of every show and episode (`entities.json`) and one file each (`entity.json?kind=&slug=`); a name in a list is a link where the index has it (the page reads the index on the server and takes only the slugs of the names it holds, `slugsMentioned`), plain text where it has not. The slug is the letters of the name and a hash of all of it. A show's picture is `podcast_show_info.image_url` (only on the hosts of `packages/intl/src/podcast-covers.ts`, Apple's asked for at 300 px): `entities.json`, the library and `entity.json` carry its path, `covers.json` lists path and address for `scripts/fetch-podcast-covers.ts`, which lands them under `.data/raw/podcast-covers/` and `web/public/covers/` after the snapshot; an episode has its show's. The shows that lead are a gallery |

Commands from `apps/podkast`: `npm run snapshot`, `npm run deploy`. A new show that is scrobbled (so that it leaves
music): see `apps/music/AGENTS.md`, "split-podcasts". A scrobble with a headline as the artist and no known show
counts as a show of its own, so the show list is longer than the shows there are.
