# AGENTS.md — tv

> **Serving (changed 2026-11):** this app is no longer a Cloudflare Worker with a published snapshot. It is Astro on Node, one of the eight media apps in the single server on the owner's machine (`scripts/media-server.ts`, the `media` container, `docs/MEDIA-SERVER.md`): dynamic server rendering, the database opened read-only, behind the owner's Nextcloud login (so "public" below means "behind that login"). Built with `npm run media:build`, live after `systemctl --user restart media`. There is no `<app>-publish` timer, no `npm run deploy` and no `wrangler.jsonc` any more; where this file says snapshot, publish or Worker for this app, read it as the server's live read of `.data/`. The sync timers stay.

`sky.lmfaole.party/apps/medier/tv`: the series the owner has watched, episode for episode, and what the TV register
TMDB says about them, a snapshot of `.data/tv.db`. Public and not indexed (the three layers, as music). Rules shared
with every app are in the root `AGENTS.md`; the counting, the lists and the pages themselves are
`@designsystem/watch`, shared with film.

There is no account to fetch the history from, so **the log is the record**: `.data/tv-log.csv`, written by hand
(`watched_on,series,year,season,episode,rating,rewatch,note,tmdb_id`, `#` starts a comment; an empty `watched_on` is a
viewing whose day is not known, and an empty `season`/`episode` is a viewing of the series as such). `tv-sync
import-log` makes `tv_watch` exactly the log's rows; a line changed or deleted in the log is changed or deleted in the
database. What the owner **has or wants** is the collection: `.data/tv-collection.csv` (`added_on,series,year,status,rating,note,tmdb_id,format`; `status` is `owned` or `want`), made `tv_collection` by `tv-sync import-collection`, and a series not seen has a page of its own (TV has no library page). `format` is what the owner has (`blu-ray`, `dvd`, `digital`; free text, lowercase) and is shown as «Eier» on the work's page. `tv-sync add <series> <year> <season> <episode> <date> <rating>` appends one episode and imports, and
`tv-sync add-season <series> <year> <season> <episodes> <date> <rating>` appends a whole season, each episode on the
same day (`-` for none). The rating is the episode's; a series' rating is the average of its rated episodes.

| Where | What |
| --- | --- |
| `sync-rust/src/apple.rs` | `tv-sync import-apple <folder>`: what Apple TV and Apple TV+ played, from Apple's data export, into `apple_tv_play` (unmatched, apart from `tv_watch`; `docs/DATA.md`) |
| `sync-rust/src/log.rs` | The log: reading and checking it (a wrong line is refused with its line number), `import`, `append`; the shared reading is `shared_data::watch_log` |
| `sync-rust/src/airdates.rs` | `tv-sync air-dates <tmdb_id>`: moves a series' viewings to the day each episode came out (TMDB's season answers, landed under `.data/raw/tmdb/<date>/`; the old log is kept as `tv-log.csv.before-air-dates`, and the job refuses to run over an existing copy) |
| `sync-rust/src/episodes.rs` | `tv_episode`: each season of the series in the log as the register lists it (name, day, length), fetched with `tmdb`; the latest season of a running series again on a refresh. `air-dates` reads the days from it |
| `sync-rust/src/main.rs` (`add-series`) | `tv-sync add-series <series> <year> [date]`: a series seen as a whole as one line, which `tmdb` and `expand` turn into its episodes; a series already in the log is left alone. `npm run seen` does it for a list |
| `sync-rust/src/expand.rs` | `tv-sync expand`: a whole-series line of the log (no season or episode: «I have seen it») becomes a line per episode that has come out, on its release day, from `tv_episode`; run `tmdb` first, which fetches the episodes. The log is copied to `<log>.before-expand` first |
| `sync-rust/src/trakt.rs` | `tv-sync trakt`: appends the episodes of the public Trakt history (`TRAKT_USER`, `TRAKT_CLIENT_ID`, a free app key) that the log lacks, matched on the series' TMDB number; pages landed under `.data/raw/trakt/<date>/`, existing lines never touched, and an episode the log has is not added again whatever day it is on. Trakt's dates are when it was marked, so `air-dates` can move a bulk-marked series to its release days |
| `sync-rust/src/trakt_push.rs` (the sign-in is `shared_data::trakt`, shared with film) | Two-way Trakt: `tv-sync trakt-login` (once; the device code is approved at trakt.tv/activate; `TRAKT_CLIENT_SECRET` only for an app that has one, not for PKCE; the tokens are in `~/.config/trakt.json`, mode 600, renewed on their own) and the push at the end of `trakt`: for each episode the log has, Trakt must hold the log's days, else its plays of it are removed and the log's days added. The log is the record: an episode only Trakt has is pulled into it first, and a line removed from the log is never removed from Trakt. `trakt --dry-run` says what it would write. Signed in, the history is read from the account's own `/sync/history` list: the public one is cached by Trakt for about twenty minutes, and a write read back from it looks undone |
| `sync-rust/src/tvmaze.rs` | `tv-sync tvmaze`: when the next episode of each series comes out, from TVmaze (free, no key; `tv_next`, originals under `.data/raw/tvmaze/<date>/`); daily. The series page shows it as «Neste episode» |
| `sync-rust/src/tmdb.rs` | `tv-sync tmdb`: looks each series and year up in TMDB (`TMDB_API_KEY`: a v3 key, or a v4 token starting «eyJ»), lands the answers under `.data/raw/tmdb/<date>/`, stores each series in Norwegian where TMDB has it (`tv_title` with ratings, seasons, episodes, the status and the ids on IMDb and Wikidata; `tv_genre`, `tv_country`, `tv_company`, `tv_keyword`, `tv_network`, `tv_credit` with the cast and the crew by job) and then every person of a credit (`tv_person`). A series no search matches is kept in `tv_match` with its candidates; settle it by writing TMDB's number in the log's `tmdb_id`. The register itself is `shared_data::tmdb` |
| `packages/contracts/src/tv-tables.ts` | The tables the pages read and `TV_VIEWINGS_SQL`: a viewing and the series matched to it (the log's number first, else the match for its title and year) |
| `web/src/server/tv-stats.ts` | TV's words for the shared counting (`TV: WatchConfig<'serie','network'>`), the shape the register's answer takes (`TvInfo`) and `seriesPageOf`, the page of one series |
| `web/src/server/api.ts`, `snapshot.ts` | `overview.json`, `history.json?year=` (the history goes a year at a time, as in games, books and boardgames; music and podkast go a month at a time), `entity.json?kind=&slug=`; the reading and the register are `@designsystem/watch/reader` |
| `web/src/pages/`, `layouts/TvPage.astro`, `views/` | Astro pages: `/`, `/historikk` and the own page of `/serie/[slug]`, `/person/[slug]`, `/network/[slug]`. Each reads its snapshot file with `readPage` and a `RESPONSES` schema (`server/responses.ts`, from `@designsystem/watch/response-schemas`); the island wrappers in `views/` (a function cannot cross the island boundary) hand it to the shared page in `packages/watch/src/pages`. Directives: `client:visible` for `/statistikk` and the three own pages (charts), plain HTML for the rest. A link to a series, person or network in a list is `?kort=<kind>.<slug>` (kinds `serie`, `person`, `network`, as `entity.json` is snapshotted): `TvPage` reads it, loads the thing and sends the `Detail` card island (`client:idle`) only then |
| `web/src/words.ts` | What TV says: `words` (`satisfies WatchWords<'serie','network'>`), `seriesFacts`/`seriesLinks` (the register's own facts of a series, which travel with the answer) and the register's `STATUS` in Norwegian |
| `scripts/fetch-posters.ts` | After the snapshot: lands the posters it names under `.data/raw/posters/` and copies them to `web/public/posters/` (`scripts/images.ts`, shared with music's covers) |

Commands from `apps/tv`: `cargo run -p tv-sync -- import-log | add … | add-season … | add-series … | expand | trakt-login | trakt [--dry-run] | tvmaze | air-dates <tmdb_id> | tmdb [--refresh | --everything]`, `npm run snapshot`, `npm run deploy`.
Timers: `schedule.json` runs `import-log` and `tmdb --refresh` daily: new series, and of the stored only what TMDB's change lists name since the last read (`tv_tmdb_checked` keeps how far they vouch), plus at most 150 a run of those fetched before that; `--everything` fetches all (`node scripts/sync-timers.ts tv install`, with `TMDB_API_KEY` in `~/.config/tv-sync.env`, mode 600), and `node scripts/publish-timers.ts tv install` publishes after it.
The pages show TMDB's credit (`TmdbNotice`): the terms ask for it, and for the page to say it is not endorsed by TMDB.
